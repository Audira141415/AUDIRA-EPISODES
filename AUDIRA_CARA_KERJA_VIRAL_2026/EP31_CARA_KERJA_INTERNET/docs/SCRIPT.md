# SCRIPT — Cara Kerja Internet (EP31)

**Format:** Short 9:16 | **Style:** CIRCUITFORGE | **Engine:** Remotion + R3F
**Target:** 200–220 kata | 135–150 WPM | ~85–95 dtk

---

## S1 — Hook (0–3 dtk)
Setiap kali kamu klik, datamu melewati dua puluh router dalam lima puluh milidetik.

## S2 — Context (4–15 dtk)
Tapi bagaimana caranya? Saat kamu membuka sebuah situs, ponselmu mengirim permintaan ke DNS — buku alamat internet. DNS menerjemahkan nama situs menjadi alamat IP, lalu mengirimnya kembali ke ponselmu.

## S3 — Main Development 1 (16–35 dtk)
Sekarang ponselmu tahu tujuannya. Datamu dipecah menjadi paket-paket kecil, masing-masing maksimal seribu lima ratus byte. Setiap paket diberi alamat pengirim dan penerima. Paket-paket ini melompat dari satu router ke router berikutnya — setiap lompatan disebut hop. Rata-rata, dibutuhkan sepuluh sampai dua puluh hop untuk sampai ke server tujuan.

## S4 — Main Development 2 (36–50 dtk)
Untuk jarak antar-benua, paket melewati kabel serat optik bawah laut. Ada lebih dari lima ratus lima puluh kabel membentang di dasar samudra, total satu koma empat juta kilometer. Cahaya di dalam serat optik merambat dua ratus ribu kilometer per detik — dua per tiga kecepatan cahaya.

## S5 — Explanation (51–72 dtk)
Sampai di data center, server memproses permintaanmu dan mengirim jawaban — dipecah lagi jadi paket-paket kecil lewat jalur yang bisa berbeda. Di ponselmu, protokol TCP merakit ulang semua paket sesuai urutan. Kalau ada paket hilang, TCP minta kirim ulang. Makanya koneksimu tetap utuh.

## S6 — Visual Payoff (73–85 dtk)
Satu klik. Dua puluh router. Lima ratus lima puluh kabel bawah laut. Dua ratus ribu kilometer per detik. Dan semua itu terjadi sebelum halaman selesai dimuat.

## S7 — Outro (86–90 dtk)
AUDIRA.
